- **[BUG]** The report page (`/[date]`) is badly broken on any screen ≥1280px wide (`xl` and up - most laptops and desktops): the article and the "News/questions/actions" rail render squeezed into a ~270-390px strip flush against the right edge, with the rest of the viewport blank. Root cause found by inspecting computed styles: `Page.svelte` renders `<SyncAge/>` as an extra grid item ahead of `{@render children()}` whenever a mirrored page's own `class` prop also turns `<main>` into a CSS grid - `/[date]` is the only page that is both mirrored and does that (`class="xl:grid xl:grid-cols-[minmax(0,1fr)_18rem] ..."`), so `SyncAge`'s `<p>` claims grid cell (col 1, row 1), auto-placement then pushes the article into (col 2, row 1) - the 18rem rail track - and the rail itself down into (col 1, row 2), thousands of pixels below the fold. Fix needs `<SyncAge>` given its own explicit grid placement (e.g. `grid-column: 1 / -1`) in `Page.svelte`, or moved out of the grid's item flow entirely. Not caught by `bun run check`: `blackhole` only drives Chrome at 390×844, where `xl:` never applies, so this code path is never exercised by anything in the suite

# Dashboard

SvelteKit app in `dashboard/`. Offline behavior (mirror, outbox, service worker) is in `docs/offline-mode.md`.

## Route registry

**Every page is declared once, in `dashboard/src/lib/routes.ts`.** The entry carries the nav label, assistant surface, group, icon, child route ids, `g`-key shortcut and the flags below. The navbar, the mobile tab bar and the assistant's client-side surface fallback all render from it, and `scripts/check-route-surfaces.ts` (part of the root `bun run check`) fails the build when an entry's surface disagrees with `src/ai/surfaces.ts`. Adding a page means adding one entry there and, if it needs more than the `global` surface, one line in `ROUTE_SURFACES`.

Entry flags: `tab` (one of the mobile tab destinations: Report, Notes, Chat), `secondary` (folded into the desktop More menu), `headerIcon` (Settings), `hidden` (registered for its offline tier and surface but never rendered as a nav link; only reachable from a link inside another page, e.g. `/privacy`, `/terms`, `/setup` and the `/settings/*` subpages). The offline tier lists (`MIRRORED_ROUTES`, `STATIC_OFFLINE_ROUTES`, `ONLINE_ONLY`) live in `dashboard/src/lib/offline/tiers.ts` and `onlineOnly.ts`, see `docs/offline-mode.md`.

## Routes

One line per route; labels, groups, icons and shortcuts are in `dashboard/src/lib/routes.ts`. Only behavior and invariants stated nowhere else are kept here.

Report:

- `/[date]` - the daily report: Section 2, then the News section, then Section 1. Tapping an entry expands its sources in place (clicks on a link or button inside it and text selections don't count); the thumbs rating lives inside that expansion, never beside the collapsed prose. There is deliberately no expand button: the cue is a chevron after the entry's last word (`.entry-prose` in `app.css`), a hover/press tint, and a one-time `EntryHint` (per-device `localStorage` flag). Personal entries carry `QuickActions`; any the report never mentions sit in their own block at the end of Section 2. "Play this briefing" (online only) opens `ReportPlayer`, a singleton (`player.svelte.ts`) mounted in the root `+layout.svelte` (logged in only), so it keeps playing across route changes and stops only when the audio ends or the user closes it; the button is hidden only on the day currently playing, so another day's report can replace the current briefing. It requests only the current and next chapter, so skipping never pays for skipped chapters. The seek bar (`SeekBar.svelte`) is one segment per chapter, YouTube-style: a quick tap within 14px of a chapter edge (or a third of a short segment) snaps to that boundary, a tap elsewhere seeks exactly, and holding 350ms or dragging 8px scrubs freely with a live preview and seeks on release; Enter/Space on a segment starts that chapter. While it plays, the entry being read is highlighted (`bg-primary-950`, `aria-current`). The speech endpoint returns no timings, so `player.activeEntry` estimates it from the playback position by character share over each chapter's `segments` (`active-entry.ts`); entry ids are `p:group:entry`, `n:group:entry`, `i:group:entry` and `a:entry`, matching indices in `ReportJson` and passed as `entryId` to `ReportEntry`. Entry-level only (the spoken text differs from the rendered DOM, so sentence-level would drift), and the page does not auto-scroll. Audio comes from `src/audio/store.ts` (see `docs/architecture-rules.md`). `IngestWarning` sits above the briefing whenever a source failed to deliver, because Phase 1 carries on when one dies and the report otherwise reads as complete. Below `xl` the section tabs are a floating pill under the header; at `xl` they move into the sticky right rail. When the report has a structured body, `ReadProgress` (`src/lib/report/ReadProgress.svelte`) shows a thin bar fixed above the transparent header (overlay, no layout shift) that slides in on the first scroll, plus a "N min left" chip under the header at the right (words in the article below the reader at 230 wpm, re-measured by `ResizeObserver`); below `sm` the chip is hidden and only the one-time celebration shows, at the bottom center above the tab bar. Reaching the end after a real scroll triggers that short non-blocking celebration (~2s, `pointer-events: none`, reduced motion handled by the global rule). It is purely client-side and independent of the read receipt, which still POSTs on reaching the end.
- `/[date]/detail/[ids]` - the extractions behind one entry: the shareable deep link and the no-JS fallback for the inline expansion. Each non-news card has an online-only "Fetch contents" button that reads the stored mail body from `GET /api/extractions/[id]/raw` (`no-store`); the body lives only in component state and is dropped on "Hide contents" or navigation, never written to the mirror.
- `/[date]/triage` - everything that arrived on that run and where it stopped: dropped at ingest, never extracted, dropped at the gate, seen by synthesis and passed over, or cited. Filter chips per outcome plus search; linked from the report's "filtered" figure.

Intelligence:

- `/sources` - source quality list (trust scores, include rates, last delivery). Each row links to "Details"; "Enable" appears only for disabled sources. Enable writes straight to Postgres (`dashboard/src/lib/server/sources.ts`), so it works without the pipeline server; failures come back as a toast.
- `/sources/[name]` - every delivery from one source and what extraction made of it. The only place a source can be hard-deleted: its scores and polling/matching settings are erased, past reports and their data are not. Optional "also open unsubscribe link" when one was found at ingest.
- `/entities` - entity explorer (filterable table); search matches name, aliases and summary.
- `/entities/[id]` - one entity: a Watch control (sets `importance = 'high'` through the correction path, feeding the monitoring search slot) and its appearances as a timeline.
- `/topics` - `active_topics` with resolve and archive. Curation only: no skill may write this table.
- `/contacts` - the sender directory. Edits go through `recordCorrection`, so they behave exactly as the assistant's do.

Memory:

- `/notes` - masonry cards, search, scope chips, trash, bulk select. All creating and editing goes through one `NoteEditor`: one PATCH so one edit is one revision, explicit Save/Cancel with no blur-save, drafts kept in the page. The editor's collapsed "Where it loads" section (`NoteTargeting.svelte`, deliberately below the Save row so Save stays clear of the phone bottom bar) edits steps (chips), senders/entities/keywords (comma-separated) and the start day. Cards show targeting badges and a load line ("loaded Nx, last D", or "never loaded", amber when dormant; tracking is recent, so "never loaded" is unreliable for the first 30 days). A "More filters" disclosure (open while one is active, `NotesNarrowFilter.svelte`) holds narrowness chips, "Not loaded in 30 days" with a count, a step select and a sender/entity text filter; they live in the URL as `narrow`, `step`, `target`, `dormant` (`lib/notes/filterUrl.ts`). History (online-only) opens in a modal `Sheet` as word diffs with "Restore this version". Scope colours and hints are `SCOPE_INFO` in `lib/notes/api.ts` (`contact` is "Reference only": no briefing reads it yet). Only the first 200 notes are shown, with a line saying so. System notes are editable; provenance shows via `created_by` / `updated_by` (`harvest` reads "Keep import"). The standing rules from Keep are ordinary `personal` notes edited here; there is no separate rules page. A trashed rule seeded from Keep (`source_key` set) says it is kept so Keep does not re-add it, instead of "purged after 30 days". The filter lives in the URL, written with a shallow `goto`, so `page.url` stays the loaded URL and the written one is in `page.shallow.url`: the page reads `page.shallow?.url ?? page.url` (`shownUrl()`), never `page.url` alone, or the next mirror invalidation reads the unchanged real URL as a navigation and resets the filter. `/entities` does the same.
- `/context-builder` - the harvested document, source summaries and run controls (Start, Force full, which asks for confirmation because it re-extracts everything, Stop). Only at `xl`+ does a Quick Links rail sit beside the document (always rendered, even with no document), ending in links to `/notes?scope=personal` and `/context-builder/corrections`; below `xl` the page has no direct link to either.
- `/context-builder/corrections` - the active `context_corrections` over the harvest; a revert is written on the server, never queued.

Questions and assistant:

- `/questions` - the open question queue. Each question is answered or dismissed on its own; recently closed ones show the reason and a reopen. Item questions sort first, then newest asked; assistant-raised ones are badged "Asked by the assistant". Briefings never wait for answers, and answering makes the assistant act right away (the `questions` surface).
- `/questions/closed` - recently closed questions. An answered one shows what the assistant did (`running`, applied or failed), its own account of the change, a "See every step" link to the chat transcript (`/chat?c=<id>`), and "Run again" unless it already succeeded.
- `/chat` - the assistant full screen: the same `Panel` as the floating widget, sharing its live conversation. `?c=<id>` opens that conversation; no param (or `?c=new`) is an empty composer, so a reload or direct visit starts a new chat. The open id lives only in in-memory assistant state, so a client-side navigation to bare `/chat` redirects onto the live conversation with `replaceState` (keeps Back from looping).

System:

- `/skills` - the pending high-risk approval queue and the read-only registry with an enable/disable toggle, search and sort; a row's 30-day usage counts non-pending `skill_executions` rows. `/skills/executions` is the last 100 non-pending executions.
- There is no prompts page: prompt versions have no dashboard UI. The assistant proposes one through `propose_prompt_version` (high risk), which parks on `/skills`; confirming there inserts and activates it, rejecting stores nothing. The pending queue renders parameters with `ParamList.svelte`, which shows long strings (a prompt) in a wrapping, height-capped box. The pipeline API has no route that touches `prompt_versions` (no list, read, activate or delete), while the weekly prompt review remains. There is no `prompts` assistant surface either: `propose_prompt_version` lives on `global`, so the assistant can propose a version from any page.
- `/runs` - `pipeline_runs` history with duration and cost trends and the per-attempt error log. A failed or degraded run not yet reviewed carries "Mark reviewed" (the `reviewRun` form action) and is what the Runs badge counts; RSS feed failures count as run issues here. A run with audio cost shows "$X audio" in its row.
- `/runs/[id]` - one run's step timing from `pipeline_run_steps`: the Time card opens with a small stats row (`InlineStats`: total, without-the-wait only when the run waited, step count, failed attempts only when any), then one summary bar (`TimelineBar`, segments from `timelineSegments` in `$lib/runTimeline.ts`) coloured per phase on the run's time axis, with equal-width diagonal stripes, one colour per running phase, where 2-3 ran in parallel (stripes continue across neighbouring parallel stretches at any width: `timelineSegments` keeps a group's stripe slot, and each fill is a window onto one gradient sized to the whole bar); the News editor counts as Synthesis, so "News desks" covers only the desks, the phase legend directly after the bar, a collapsed native "Details" list of steps (`StepTimeList.svelte`) with the duration right after the step name (steps whose name is not self-explanatory, per `$lib/runStepHints.ts`, get a dashed underline, a small "?" and a hover title), a callout when the old question-gate wait dominates (present only on historic runs, and can be shrunk), and a Cost card from `$lib/pricing.ts` that mirrors the Time card (same `InlineStats` row with total, tokens in/out, model calls and searches, then a share bar in `CostShareBar` with the time bar's height and gapless look and the phase legend directly after it; the per-phase and per-step tables collapsed under "Details"), plus a separate "Audio cost" card after the run cost when the report was spoken (an estimate, not part of the run cost). A "Jev decisions" card (`JevDecisionsCard`) aggregates `jev_decisions` per task and mode (calls, failures with error codes, input tokens, avg and max latency, decisions that influenced the report); shown only when the run has rows, kept apart from the run cost because Jev is a different provider, and absent while the table is missing (the query degrades to no card). Online-only; empty for runs before 2026-10-01.
- `/settings` - see below.
- `/settings/email-accounts` - live IMAP/SMTP accounts as a card list. Add and edit share one `Sheet` form with Save/Cancel in the pinned `footer`; the sheet closes only on success and shows a failed save inline in the footer (the native dialog sits in the top layer and covers the toast). Delete lives at the bottom of the sheet body.
- `/settings/newsletters` - live RSS feeds; a feed's latest fetch error sits below its URL, and removing the row stops polling it.
- `/settings/newsletters/rules` - live sender rules routing a sender to a newsletter source before extraction; exact addresses win over domains.
- `/login`, `/setup` (passkey and PIN management), `/privacy`, `/terms` - public pages outside the nav (`/privacy` and `/terms` are prerendered).

### `/settings`

Mirrored offline like the rest of the page, except the language fields, which need the connection (the theme select is device-local and works offline). The page has no server load.

- **App card** (`InstallApp`): an Install button whenever PIDRA is not installed. It is enabled once the browser has offered its install prompt; otherwise disabled with manual steps (iOS Share > "Add to Home Screen", or the browser menu). It also has an installed state, and "Open the app" only on desktop Chromium, the one place a tab navigation is captured into the installed app. There is no uninstall control because no browser exposes one, and the UI never says "PWA".
- **Install-prompt plumbing**: Chrome fires `beforeinstallprompt` once, ~100 ms after load and before hydration, so a small inline script in `app.html` stashes it on `window.__pidraInstallPrompt` and `pwa.start()` in the root layout (`$lib/pwa.svelte.ts`) picks it up. The script's sha256 is `INLINE_INSTALL_PROMPT_HASH` in `hooks.server.ts` (report-only CSP): change the script and the hash goes with it. `app.html` has a second hashed inline script that applies the stored theme before first paint (`INLINE_THEME_HASH`, same rule).
- **Installed-app detection** (`getInstalledRelatedApps`, which needs `related_applications` in the manifest) runs only from the card, never while offline, and is abandoned after 3 s: it makes the browser re-fetch the manifest with no way to cancel, so the blackhole suite treats `/manifest.webmanifest` as a browser-owned request.
- **Preferences**: a Theme select (Dark default, Light, System) stored per device in `localStorage` key `pidra:theme` and managed by `$lib/theme.svelte.ts` (`loadTheme` from the root layout, `setTheme` from here). It works offline and touches no API or DB. The content-language select (what briefing, questions and chat are written in; applies from the next briefing) saves on change with a toast, and is disabled until the stored values load and while offline. The interface-language select is permanently disabled ("Translations coming soon") until Paraglide lands (`docs/todo/later.md`). Both go through `GET`/`PATCH /api/settings`, validated against `src/config/languages.ts`.
- Then links to account and source configuration.

## Navigation

Rendered from the registry; registry order is the order everywhere.

- **Desktop (`lg`, 1024 px, and up):** the row shows only the non-`secondary` entries (Report, Notes), icon-only. Everything else sits in the More menu, a 3x3-dots button opening a three-per-row grid of icon tiles in registry order: Questions, Chat, Sources / Contacts, Entities, Topics / Context, Skills, Runs (9 items). Settings is an icon-only header button at every width, last. No dividers, transparent header (a fill appears once the page scrolls).
- **Mobile:** a bottom tab bar (`tab` entries: Report, Notes, Chat) plus a More sheet, a three-column grid of the same tiles as the desktop More menu so every destination shows without scrolling (offline-only tiles are dimmed, the "needs the connection" message kept for screen readers). `secondary` only affects the desktop navbar. `Sheet` takes an optional `footer` snippet pinned below its scrolling body, for the actions of a long form. Every phone bottom drawer (the More sheet, `Sheet`, `SyncSheet`) closes with a swipe down through the `swipeToClose` action (`$lib/ui/swipeToClose.ts`): the drawer follows the finger and closes past 96 px or on a quick flick, otherwise springs back. A drag starts only on a downward move while the drawer's content is scrolled to the top, so long content still scrolls.
- **Badges:** `GET /api/nav-badges` returns counts keyed by href (`/` unread reports, `/questions` open questions, `/runs` unreviewed failed or degraded runs, `/skills` pending approvals), shown as a red `CountBadge` on each page's button and summed on More (`Navbar` sums the tiles inside it, `TabBar` the tiles of its sheet). Counts refresh (`navBadges.refresh()`, throttled to once per 5 s) on page data reloads and after the read receipt, and unthrottled (`{ force: true }`) when the service worker posts `pidra:mirror-changed` after a push-triggered sync, so a report arriving while the app is open shows its (1) without navigation; the root layout also polls every 60 s via `poll.ts` (paused while hidden or offline). There is no notifications page or bell. Unread reports are acknowledged by reaching the end of the report (`POST /api/notifications/report-read/[date]`); run issues with "Mark reviewed" on `/runs`.
- **Header:** the logo (`SyncLogo`) is the sync control; the "PIDRA" wordmark next to it links home, hidden between `lg` and `xl`, where the Report button is the way home. The "A new version of PIDRA is ready" notice lives in the navbar: centered from `md`, a refresh icon with a dot on phones.

## Floating assistant

Mounted once in `+layout.svelte`, so it is reachable from every page and a turn survives navigation. Each page declares what it shows with `setPageContext()` (`$lib/assistant/state.svelte`); the `focus` list hands the model real ids for the rows on screen. Turns stream over SSE (`POST /api/assistant/chat`), tool calls appear as they run, and a turn that wrote something triggers `invalidateAll()` plus a highlight on the changed rows. Hidden on `/chat` (the same thing full screen) and below `sm`, where the bottom bar's Chat tab replaces it.

## Conventions

- **Layout:** pages are wrapped in `<Page size="read|app|form|legal">`, which owns container width (`--container-*` in `app.css`) and responsive padding. `legal` is wider than `read`, for prose pages.
- **No visible `<h1>`** on the list and management pages (`/sources`, `/contacts`, `/settings`, `/topics`, `/runs`, `/skills`): the tab title (`Page`'s `title` prop) and the nav say where you are. The blackhole layout check wants content spanning at least 90% of the frame, so a page whose body is a capped column (like `/settings`) wraps it in a full-width div instead of relying on a full-width heading.
- **Formatting helpers:** dates and numbers through `$lib/format.ts`, DB enum values through `$lib/labels.ts`, cost through `$lib/pricing.ts`.
- **Markdown:** every `{@html}` goes through `renderMarkdown()` in `$lib/markdown.ts`; nothing else may call `marked`. A DOMPurify `afterSanitizeAttributes` hook adds `target="_blank" rel="noopener noreferrer"` to `http(s)` links so briefing links open in a new tab; authored `target`/`rel` stay forbidden, and internal and `mailto:` links are untouched. Hand-written external `<a>` tags outside `renderMarkdown()` (e.g. the news source links in `ExtractionCard.svelte`) carry the same two attributes.
- **Buttons and panels:** a button is `btn` + one size/shape (`btn-sm|md|lg|step|bare|icon|round`) + one tone (`btn-primary|solid|ghost|danger|surface|quiet|quiet-danger|flat|accent`). `btn` no longer sets the radius, so the size supplies it (`btn-bare` is `rounded px-2` and leaves the text size to the caller; `btn-step` is the larger prev/next day control; `btn-icon` / `btn-round` are the icon-only shapes, `rounded-lg` / `rounded-full` with no padding, and the caller sets `h-N w-N`; `btn-surface` is panel-coloured with the panel shadow; `btn-quiet*` have no fill and no visible border, for dismiss/history/inline actions; `btn-flat` is borderless and lights up on hover, the player's transport controls; `btn-accent` is the filled primary control, the player's play button). A filter pill is `chip` + `chip-on|off`, and a panel is `<Card>` (`$lib/components/Card.svelte`: `as` div|section|article|li|ul, `tone` default|inset|warning|error), not a pasted `rounded-lg border ...` string. Tones never set the same property, so they compose in any order. `app.css` gives `button:not(:disabled)`, `summary` and `[role="tab"]` `cursor: pointer` globally: never add `cursor-pointer` to a button. `nav-btn` carries its own disabled styling.
- **Shared pieces** in `$lib/components/`, used instead of pasting markup: `Field` (labelled input/textarea/select), `Tabs` (underline `role=tab`) and `Segmented` (`aria-pressed` buttons), `NavLink` (variants icon/tile/tab; owns badge, offline unavailable state and `aria-current`), `Disclosure`, `JsonBlock`, `UsageTable` and `LegalPage`/`LegalSection`. DataTable columns take `value: (row) => string` and `class` before a cell snippet is needed. Popovers and dropdowns close through `use:dismissable` (`$lib/ui/dismissable.ts`: Escape plus outside press), not scrim buttons or window key handlers.
- **Icons** come from lucide (`@lucide/svelte`, imported per icon from `@lucide/svelte/icons/<name>`); emoji are never icons. `dashboard/static/icons/icon.svg` is the single source for the header logo, favicon and PWA icons: editing it means regenerating the PNGs beside it.
- **Language and palette:** the interface is English throughout, including the assistant's surface hints, until Paraglide is installed and `user_settings.ui_language` takes effect. The palette is dark by default, with light and system (OS-driven) selectable per device in Settings: every ramp stop in `app.css` is a `light-dark(light, dark)` pair and `color-scheme` on `:root` follows `html[data-mode]`. The ramp is mirrored (stop N in light is stop 1000-N of the standard ramp), so Skeleton's own `--color-surface-A-B` pair tokens (used by global `code`, placeholder colour, tap highlight, kbd/blockquote/hr rules) would flip twice in light mode; `app.css` re-states each as a plain alias of one mirrored-ramp stop (pair A-B is always A and 1000-A, so both sides are the same var; dark mode is unchanged) - leave them, or inline code goes near-white on a pale chip. Modal and drawer backdrops use `bg-(--app-scrim)` (dark in both modes), never `bg-surface-950/NN`, which is the page colour in light mode and dims nothing. Light mode lifts `.bg-surface-900.border.rounded*` cards with `--app-shadow-panel` (resolves to transparent in dark; set in the components layer so explicit `shadow-*` utilities still win). Don't lighten `surface-500` for softer borders: `text-surface-500` is real text in many places. `dashboard/scripts/contrast.ts` enforces the contrast floor in both modes on every check; it parses the `--color-*: light-dark(light, dark)` declarations out of `app.css`, so there is no second palette to keep in step, and it fails if a checked pair names a stop `app.css` lacks.
- **Prose CSS:** the `.report-body` and `.chat-body` rules live in `dashboard/src/lib/report/prose.css`, imported from `app.css` right after the Skeleton imports (`@import` must come first). Keep new markdown-body styling there, not in `app.css`.
- **Phone first:** a change is checked at 390x844 on a real device before it counts as done. A desktop viewport resized narrow is not that check. The blackhole layout lane covers 1024, 1280, 1366 and 1920 px; the desktop shell (navbar row, no tab bar, floating assistant) starts at `lg`.
- **Offline:** every page belongs to exactly one offline tier and no client code calls `fetch` directly; both rules are in `docs/offline-mode.md`.
